# Decisions

| # | Date | Decision | Why | Alternatives |
|---|------|----------|-----|--------------|
| 1 | 2026-10-14 | Single Python/FastAPI backend, React+TS frontend | AI, OCR and NLP libraries are Python; one service is simpler | Node API + Python worker (more moving parts, no benefit yet) |
| 2 | 2026-10-14 | PostgreSQL full-text search as keyword baseline | Already need Postgres; built-in ranking and highlighting; no extra infra | Elasticsearch/OpenSearch (extra service), SQLite FTS5 |
| 3 | 2026-10-14 | Chunks never cross a page boundary | Every passage cites exactly one page | Section-aware chunking (revisit for RAG quality) |
| 4 | 2026-10-14 | Manifest file (`data/manifest.json`) is the source of truth for metadata | Reviewable in git, re-ingest is reproducible | Upload form in UI (later, if needed) |
| 5 | 2026-10-14 | Original PDFs kept in `data/raw/`, not committed to git | Keeps repo small; manifest stores URL/DOI + sha256 to re-obtain and verify | Commit PDFs (only if licence allows and size is small) |
| 6 | 2026-10-14 | `pgvector/pgvector:pg16` Docker image for local DB | Ready for semantic search milestone without changing DB | Separate vector DB (not justified) |
| 7 | 2026-10-16 | Embedding model: intfloat/multilingual-e5-small (384 dims) run with ONNX Runtime | Free, local, CPU-friendly, covers ~100 languages incl. Tamil for the next milestone; ONNX Runtime is a ~15 MB install vs PyTorch's hundreds of MB | paraphrase-multilingual-MiniLM (similar size, weaker retrieval training), larger e5/bge-m3 (too slow on CPU), paid embedding APIs (cost, data leaves the laptop) |
| 8 | 2026-10-16 | Hybrid = Reciprocal Rank Fusion, k = 60, top 50 of keyword-any + top 50 of semantic | Uses ranks only, so ts_rank_cd and cosine scores never need normalising; standard k from Cormack et al. (2009); keyword-any because keyword-all returns nothing for most questions | Weighted score sum (needs per-method normalisation and tuning on the same small test set) |
| 9 | 2026-10-16 | Exact vector search, no HNSW/IVFFlat index | 677 chunks scan in milliseconds and exact results keep the evaluation reproducible | HNSW index (add when the collection reaches tens of thousands of chunks) |
| 10 | 2026-10-16 | Vectors stored in `chunks.embedding` with `chunks.embedding_model`; `python -m app.embed` fills only missing ones | Re-runs are cheap; re-ingesting a document clears its vectors automatically; a model change is detectable | Separate embeddings table (more joins, no benefit at this size) |
| 11 | 2026-10-18 | Spelling variants are an explicit, hand-checked list (`app/normalize.py`), each group with its evidence page; applied to keyword search only | A variant is added only when our documents show the spellings mean the same thing; eri/kanmai/oorani and the water-manager role names are deliberately not merged. Semantic search already tolerates spelling. | Automatic fuzzy matching or edit distance (would merge different Tamil words), transliteration library (not checked against these sources) |
| 12 | 2026-10-18 | Evaluation counts each page once, at its first rank; old runs re-scored from their saved result lists | Labels are per page, so a repeated page inflated P@5; re-scoring saved lists compares V2 and V3 on identical retrieval output | Keep old rule (unfair to V2 vs V3), re-run V2 code (needs old checkout and the laptop) |
